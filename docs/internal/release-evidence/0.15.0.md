## Post-Deployment Comparison Correction

The maintainer reported that Compare slot hid the current results without
showing its comparison view. This was reproduced by making the UI harness
invoke dropdown initialization immediately, as the
[Classic client implementation does](https://raw.githubusercontent.com/Gethe/wow-ui-source/classic/Interface/AddOns/Blizzard_SharedXML/Classic/UIDropDownMenu.lua).
The reference dropdown iterated a missing equipment-context array during
construction. The interrupted constructor cached a partial comparison frame;
later layout hid the results before failing on another missing control.

The correction initializes complete comparison state before constructing
controls, publishes the frame only when construction completes, and restores
the originating view if opening fails. The shared harness now invokes the
native initialization callback immediately. All nine existing comparison tests
failed with the corrected harness before the fix; 134 other UI tests passed.
New regressions cover initial display, reentrant layout, failed construction,
and retry. Final focused results and redeployment hashes are in the task
handoff. The earlier full-data gate passed at `f120969750aeec6ac9d628e040672ea9379b05d2`;
it must run again from the final clean release commit before publishing.
Client verification remains pending after this correction.
