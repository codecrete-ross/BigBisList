# 0.13.0 Release Evidence

## Scope

This minor release updates Anniversary compatibility to interface 20506 and
changes Pre-Raid to follow the active content schedule. Stable PR, T4, T5, T6,
ZA and SWP identifiers, manual raid selections, saved variables, ownership,
wishlists and public slash commands remain compatible. There is no additional
Pre-Raid selector or version-profile UI.

The update refreshes registered endgame guide evidence and acquisition
dependencies, adds phase-specific gem and enchant guidance, and retains earlier
alternatives. Leveling ranking documents were not refreshed; shared runtime and
acquisition behavior are included in validation.

## Content Schedule and Client Review

- Reviewed Blizzard's [raid launch confirmation](https://us.forums.blizzard.com/en/wow/t/new-raids-open-at-300-pm-pdt-on-august-27/2340643/1)
  on 2026-09-04. Tier 6 remains August 27, 2026 at 22:00 UTC,
  `1787868000`. The same post confirms the expected heroic epic-gem changes
  and identifies the following weekly reset as the Season 3 start.
- Stable content definitions are separate from `tbc_anniversary_2026` in
  canonical data. Previously verified Tier 4 and Tier 5 dates are retained;
  unannounced ZA and SWP dates remain unset. Source phase-number mappings are
  explicit and distinct from player-facing content names.
- Read-only executable metadata identifies the installed Anniversary client as
  `2.5.6.69546`. The TOC uses `20506` and keeps `@project-version@`.

## Evidence and Limitations

- `data/raw/wowhead/refresh_report.json` records fresh guide and dependency
  retrievals, prior-release ranking fingerprints, endpoint fallback methods,
  and failures. A fresh capture alone is not counted as a ranking change.
  The run retrieved 185 distinct guide URLs and 3,457 dependency URLs with no
  remaining fetch failures; 53 guide ranking fingerprints differ from 0.12.3.
- Historical Pre-Raid snapshots are retained by content phase. A phase without
  distinct verified guidance inherits only the nearest earlier verified path.
  Later catch-up lists cannot populate earlier contexts.
- Phase gem and enchant snapshots preserve loadout/prose evidence, recipe and
  spell dependencies, unverified updates, and unavailable or unresolved guide
  candidates. General enhancement guidance remains an explicitly reported
  fallback where no distinct phase guidance is verified.
- Reviewed Anniversary corrections live in canonical overrides with evidence
  under `data/raw/wowhead/phase_source_evidence` and `phase_gems`. These include
  Season 3 seller windows, profession recipes, tradeable enhancements, and
  ten-potion Mark of the Illidari purchases with reputation requirements.
- Some fresh item/spell requests expose tooltip fields without acquisition
  tables. Richer committed item-page acquisition evidence is retained in those
  cases. Unverified historical/current PvP price variants are withheld rather
  than reported as verified Anniversary discounts; eligible seller routes remain.
- The deterministic progression audit reports all spec/phase/family contexts,
  Pre-Raid inheritance, acquisition provenance, and unresolved evidence. Missing
  included acquisition, invalid inheritance, and ineligible Pre-Raid rewards
  fail the full release gate.

The [coverage evidence](0.13.0-coverage.json) records every spec/phase/family
status and every Pre-Raid inheritance origin. Its 672 family contexts include
55 verified refreshed ranking contexts, 284 refreshed but unchanged contexts,
279 general-guide fallbacks, 26 partial phase-guidance contexts with a general
fallback, and 28 groups of phase-scoped Pre-Raid paths. The 168 Pre-Raid
contexts contain 42 verified paths and 126 explicitly inherited paths. The
audit reports zero missing included acquisitions or invalid progression paths;
fallbacks and unchanged retrievals are not counted as verified ranking refreshes.

## Automated Verification

The authoritative command is:

```powershell
pwsh -File scripts/check-release.ps1 -Version 0.13.0 -PythonPath .\build\release-venv\Scripts\python.exe -FullData
```

It must run from the clean release preparation commit. The dedicated Python
environment is installed from this repository's `pyproject.toml`; the runtime
tests and compiler use Lua 5.1.

Regression coverage includes launch boundaries, a replacement release schedule,
historical snapshots and mutable URLs, explicit source terminology, exclusive
source-window ends, later sellers and recipe/token dependencies, epic and budget
gems, purchased versus raid-only Pre-Raid routes, manual selections and saved
state, and consistent index/planner/tooltip/Wishlist contexts. Exhaustive
committed-source Python/Lua comparisons cover all six progression contexts.

The first clean-commit full gate detected stale shared item facts against newly
refreshed evidence: fuller effect descriptions, class restrictions, and corrected
passive stats. The isolated `item_stats` import updates those facts and reviewed
source windows without regenerating leveling recommendations. None of the 15
items with corrected passive stats occurs in saved leveling rankings. Enriched
effect descriptions do not change the existing recommended items' passive
scores. Verified class restrictions exclude 25 incompatible archived rows at
runtime; the ranking documents remain unchanged.

The full gate result and final counts are recorded in the release handoff.

Headless Lua smoke testing exercised all 28 specs across all six contexts:
15,779 slot rows, 19,452 planner rows, 5,066 enhancement rows, and 168 tooltip
and Wishlist checks. The actual `/bbltest` handler passed with Pre-Raid and
manual Tier 4 selections, retaining both selections. In this CLI environment,
data load took 762 ms CPU and retained about 39.4 MiB; the first Tier 6 index
took 94 ms and about 4.2 MiB. Subsequent manual contexts took 48–52 ms; the
three-context cache retained about 7.8 MiB and stayed bounded when a fourth
context was requested. A cached context switch rounded to 0 ms. These numbers
are local Lua CPU/memory measurements, not in-game frame timings.

## Anniversary-Client Smoke Test

The addon was deployed to the release maintainer's Anniversary client on
2026-09-04. All 14 installed payload files were verified; the installed TOC
reports version 0.13.0 and interface 20506. Saved variables were untouched.
Installed executable metadata identifies client build `2.5.6.69546`.

The release maintainer reported "looks good, you can release" after deployment
on 2026-09-04. This records the user's successful general client check and
explicit release approval. The agent performed no computer-use interaction.
Individual checklist actions and in-game performance measurements were not
reported, so they are not claimed as completed. The maintainer's release
approval accepts this documented limitation; follow-up ownership remains with
the release maintainer for any client API, UI, saved-state or performance issue.

The full clean-commit gate passed with 390 tests before deployment. It is rerun
on the final evidence commit before tagging; its result is recorded in the
release handoff and hosted release workflow.
